## dsh-agent-session-tools v1.4.0

DeepSeek Harness 的 **Host-only 工具插件**：让模型在自己的对话里开新会话、向别的会话递消息，并只读地审计历史会话里的工具错误趋势。插件不实现任何会话逻辑——校验、持久化、去重的最终裁决权都在宿主 `ctx.sessionController`，插件只把错误变得更早、更直白。

三个工具：

| 工具 | 作用 |
|---|---|
| `session_create` | 新建**顶层会话**（不是 subagent / fork）。不带位置参数时沿用**当前会话所属的 Workspace**；默认继承当前会话的模型与思考强度 |
| `session_inject` | 向任意会话投递一条**真实用户消息**（进目标会话日志、不可撤销），`mode: queue \| steer`，可选 `requestId` 幂等键 |
| `session_error_audit` | 只读：扫 `~/.dsh/sessions` 的会话日志，按类别统计工具调用与编辑错误，返回约 40 行的**有界**摘要 |

### 为什么新会话默认落在同一个 Workspace

宿主 `session.create` 是 `workspaceId` **或** `cwd` 二选一，而只有 `workspaceId` 那条路径会把会话挂到 Workspace 上。只给 `cwd` 建出来的会话不属于任何 Workspace，界面就把它排在所有分组之外。v1.3.0 起插件按这个顺序决定位置：

1. 显式 `workspaceId` → 透传，由宿主校验（未知 id 报 `workspace/not-found`）；
2. 显式 `cwd` → 先查该目录是否已注册为 Workspace，命中就沿它归组，**不**替调用方新建 Workspace；未命中则按普通 `cwd` 创建，并在结果里明确标出未归组；
3. 两者都没给 → 找回调方会话所属的 Workspace，沿用它（新会话与当前会话同组、同目录）。

不传模型参数时，新会话继承调用方当前的 route 与思考强度；需要换 route 用 `model` / `provider`，需要回落到部署默认用 `defaultModel`。

### 幂等键的窗口缺口

宿主的去重只检查收件箱与**已落盘**历史：消息一进 turn 就离开收件箱，而它的用户消息要到 turn 开始才写盘，这中间同键的第二次调用两头都查不到，于是会再插入一条。执行器还会把同一步里的两次调用**串行**跑完，所以单纯加并发锁无效。

插件侧两层缓解：注册实例内持有「已发起的 prompt」（同键并发合并成一次，同键不同文本报错），外加一张 60 秒的已完成键账本（上限 256 条，随注册实例释放）。同键同文本在窗口内直接复用上一次回执，不再调宿主；跨进程或超窗的重试仍由宿主按历史去重。GUI、其它插件、其它进程仍会踩这个窗口，宿主侧的修法见 `docs/wiki/05-tool-contracts.md`。

`accepted: true` 只表示消息已进入目标 Agent 的收件箱，不保证最终被处理：会话被销毁时待处理消息会被记成取消并丢弃，而宿主不会把这个结果回传给调用方。这是宿主的既有行为，插件不掩盖也不重试。

### 设计要点

- 只用 `ctx.tools.register` + `ctx.effect` 的 disposer 安装能力；仅有的两块内存状态随注册实例生灭，**没有定时器、没有自有存储**。
- 取消信号一律在调用宿主之前拦截：`create` 的签名不接收 signal（创建无法中途取消），`prompt` 接收并已透传。
- 失败保留宿主 `RemoteError` 的 `code`（`session/not-found`、`agent-preset/not-found` 等），模型拿到的是一行可行动的说明而不是裸异常；空文本、相对 `cwd`、非法 `requestId`、非 ISO 的 `since` 都在扫盘或调宿主之前拒绝。
- `session_error_audit` 的每条错误正文与招错目标在提取时就截断，因此内存平坦、会话细节不会进入上下文；损坏或读不了的日志文件跳过而不是抛错。
- host-only：不声明 `dsh.client`，patch 不插 Client 行；`peerDependencies` 全是宿主自带包，唯一运行期 import 是 `defineTool`。
- 单测覆盖校验、归类、有界聚合与注册表行为；`tsc` 严格类型检查在独立配置下运行，避免用 `any` 放宽断言。仓库不含任何机器专属路径。

### 前置条件

profile 需挂载 `session-controller`（Web 模板有；裸 `headless` 没有，且它还缺该服务注入所需的 `connection` / `file-upload` / `workspace`），v1.3.0 起还需要 `workspace` 行。缺行时插件因 `inject` 不满足而不激活 —— 这是 profile 组合问题，不是插件缺陷。

### 安装

```bash
# 从 Release 资产直装（地址不带版本号，永远是最新一版）
dsh plugin --profile <profile> add https://github.com/chocobo77/dsh-agent-session-tools/releases/latest/download/dsh-agent-session-tools.tgz

# 或克隆后从源码打包（借用本机 DSH 安装的声明，仓库不含 node_modules）
pwsh -NoProfile -File pack.ps1
```

装完**重启 Host**：DSH 按包名缓存已导入模块，禁用 / 启用不会重读。

### English

Host-only tool plugin for DeepSeek Harness. `session_create` opens a real top-level Session and — since v1.3.0 — places it in the **same Workspace** as the calling Session by default, because the host only attaches a Session to a Workspace on the `workspaceId` path; it also inherits the caller's model and reasoning effort. `session_inject` delivers a real, irreversible user message to any Session (`queue` | `steer`) with an optional idempotency key; the host's dedup only inspects the inbox and durable history, which leaves a window where a same-key retry inserts twice, so the plugin holds in-flight prompts and a 60-second key ledger that collapse it to one. `session_error_audit` returns a bounded, ~40-line summary of recurring tool-call errors across persisted session logs, without letting session detail enter the conversation. No timers, no state of its own, no machine-specific paths in the repository.
