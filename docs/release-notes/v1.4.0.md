## dsh-agent-session-tools v1.4.0

DeepSeek Harness 的 **Host-only 工具插件**：让模型在自己的对话里开新会话、向别的会话递消息，并只读地审计历史会话里的工具错误趋势。插件不实现任何会话逻辑——校验、持久化、去重的最终裁决权都在宿主 `ctx.sessionController`，插件只把错误变得更早、更直白。

三个工具：

| 工具 | 作用 |
|---|---|
| `session_create` | 新建**顶层会话**（不是 subagent/fork）。不带位置参数时沿用**当前会话所属的 Workspace**；默认继承当前会话的模型与思考强度 |
| `session_inject` | 向任意会话投递一条**真实用户消息**（进目标会话日志、不可撤销），`mode: queue \| steer`，可选 `requestId` 幂等键 |
| `session_error_audit` | 只读：扫 `~/.dsh/sessions` 的 `.jsonl.zstd` 日志，归类统计工具调用/编辑错误，返回约 40 行的**有界**摘要 |

### 为什么默认要落在同一个 Workspace

宿主 `session.create` 是 `workspaceId` **或** `cwd` 二选一，而**只有 `workspaceId` 那条路会 `attachSession`**（`packages/api/session-controller/src/commands.ts:121-157`）。只给 `cwd` 建出来的会话不属于任何 Workspace，UI 把它排在所有分组之外——就是「未分类」。v1.3.0 起插件按这个顺序决定位置：

1. 显式 `workspaceId` → 透传（未知 id 由宿主报 `workspace/not-found`）；
2. 显式 `cwd` → `workspaceRegistry.resolveByPath(cwd)`，命中已注册的 Workspace 就用它归组，**不**替调用方新建 Workspace；没命中就按纯 cwd 创建并在结果里明说 `ungrouped`；
3. 两个都没给 → 用 `exec.agent.id` 找回调方会话所属的 Workspace。

实测：`session created: session-4e59b295-… (workspace: DSH插件, cwd: D:\code\DSH) (preset: standard) (model: strata/iq3_s, effort: medium)`，该 Workspace 的 `sessionIds` 里新 id 前置。

### 幂等键的窗口缺口（实测发现，非插件缺陷）

宿主的 `hasPromptRequest` 只查 inbox 与**已落盘**历史（`commands.ts:542-553`），而消息一进 turn 就离开 inbox、它的 `user/message` 要到 turn 开始才写盘 —— 这中间同键第二次调用两头都查不到，会再插一条（实测两条不同 message id 的 `splice @3/@6`，其中一条最终没落盘）。执行器还会把同一步的两次调用**串行**跑完，所以单纯加并发锁没用。

插件侧的缓解：v1.1.1 注册实例内持有「已发起的 prompt」（同键并发合并成一次，同键不同文本报错）；v1.1.2 再加 60 秒**同键账本**（`lookupRetry` / `rememberRetry`，上限 256、按龄清理、随注册实例释放）。实测同一步两次并行注入只剩一条插入。GUI、其它插件、其它进程仍会踩这个窗口，宿主侧的修法见 `docs/wiki/05-tool-contracts.md`。

### 其它实测语义

- `mode` 落点：`steer` → `target=next-step`（目标会话正跑 turn 时在下一个 step 边界被吃进**同一个 turn**）；`queue` → `target=next-turn`（成为**下一个 turn**）。
- `accepted: true` 只表示**已进 Agent 的 inbox**，不保证最终被处理：会话被销毁时 pending 会被记成 `outcome: "canceled"` 丢弃，而 `prompt` 不会把这个结果回传给调用方。
- 模型继承读的是 live Agent 运行时面 `exec.agent.model.current()`，而不是 Host 默认 route。
- 审计工具实测样本：`63 tool errors across 10 sessions with errors`，类别分布 `other 34 / edit-mismatch 15 / search-bad-path 7 / bad-args 4 / network 2 / syntax 1`。

### 设计要点

- 只用 `ctx.tools.register` + `ctx.effect` 的 disposer 安装能力；仅有的两块内存状态随注册实例生灭，**没有定时器、没有自有存储**。
- 取消信号一律在**调用宿主之前**拦截：`create` 的签名不带 signal（无法中途取消），`prompt` 带（`types.d.ts:100, 170`），README 的兼容基线里逐条写明。
- 失败保留宿主 `RemoteError` 的 `code`（`session/not-found`、`agent-preset/not-found`…），模型拿到的是一行可行动的说明而不是裸异常；空文本、相对 `cwd`、非法 `requestId` 都在扫盘/调宿主之前拒。
- host-only：不声明 `dsh.client`，patch 不插 Client 行；`peerDependencies` 全是 `workspace:~` 的宿主自带包，唯一运行期 import 是 `defineTool`。
- 78 项 vitest 单测（3 个文件）+ 严格 `tsc` typecheck；`docs/wiki/` 有 8 页 Code Wiki（含 mermaid 架构图与工具契约）。

### 前置条件

profile 需挂载 `session-controller`（`web` 有；裸 `headless` 没有，且它还缺该服务注入所需的 `connection` / `file-upload` / `workspace`），v1.3.0 起还需要 `workspace` 行。缺行时插件因 `inject` 不满足而不激活 —— 这是 profile 组合问题，不是插件缺陷。

### 安装

```bash
# 从 Release 资产直装
dsh plugin --profile <profile> add https://github.com/chocobo77/dsh-agent-session-tools/releases/latest/download/dsh-agent-session-tools.tgz

# 或克隆后从源码打包（借用宿主 checkout 的类型，本仓库不带 node_modules）
pwsh -NoProfile -File pack.ps1
```

装完**重启 Host**：DSH 按包名缓存已导入模块，禁用/启用不会重读。

### English

Host-only tool plugin for DeepSeek Harness. `session_create` opens a real top-level Session and — since v1.3.0 — places it in the **same Workspace** as the calling Session by default (the host only attaches a Session to a Workspace on the `workspaceId` path, so a cwd-only create lands outside every group); it also inherits the caller's model and reasoning effort. `session_inject` delivers a real, irreversible user message to any Session (`queue` | `steer`) with an optional idempotency key; measurements showed the host's dedup window (inbox + durable history only) lets a same-key retry insert twice, so the plugin holds in-flight prompts and a 60-second key ledger that collapse it to one. `session_error_audit` returns a bounded, ~40-line summary of recurring tool-call errors across persisted session logs without letting session detail enter the conversation. 78 unit tests, strict typecheck, no timers, no state of its own.
