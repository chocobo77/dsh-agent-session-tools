## dsh-agent-session-tools v1.4.1

v1.4.0 的行为修复与稳健性版本：无新工具、无新参数，测试 78 → 82 项。

### session_create：未知 workspaceId 现在显式报错（行为修复）

v1.4.0 的实现把 `workspaceRegistry.get(id)` 的返回值直接当结论，而宿主契约是**对未知 id 返回
`undefined` 而不是抛错**（`packages/workspace/workspace/lib/types/index.d.ts:181`）。后果：显式给一个
未注册的 `workspaceId` 会**静默降级**——在宿主默认 cwd 建出一个未归组会话，且模型选择（含宿主
把它存成部署默认的副作用）已经先行应用。这与工具描述承诺的 "Fails when … the named Workspace
does not exist" 相悖，与 `agentPreset`（未知即拒）也不一致。

v1.4.1 起：未注册的 `workspaceId` 在创建会话**之前**直接报
`session_create: workspace "…" not found (workspace/not-found)`——不创建会话、零宿主副作用。
归组逻辑其余部分（cwd 按路径反查、无位置参数时沿用当前会话所属 Workspace）不变。

### session_error_audit：不再阻塞宿主事件循环

扫描全链路异步化：目录枚举与文件读取走 `node:fs/promises`，zstd 解码经 promisify 跑在 libuv
线程池上——日志库大时一次审计不再冻结共享宿主进程。会话日志布局、分类词表、有界输出（约
40 行）与损坏文件跳过行为完全不变；`~/.dsh/sessions` 缺失或不可读现在以
`session_error_audit: … (<errno>)` 的工具错误返回，而不是裸文件系统异常。

### 打包与元数据

- `pack.ps1` / `pack.sh` 的 tarball 必含清单补上 `dist/error-audit.js`，发布前最后一道断言
  覆盖全部四个运行模块；
- Plugin Manager 中英文描述补第三个工具；
- 清理：删除无引用的 `ErrorRecord` 接口与遗留注释，`session_create` 的 JSDoc 归位。

新增测试：未知 `workspaceId` 在调宿主前拒绝、zstd 解码往返、`auditSessions` 目录遍历
（含损坏文件跳过与 `since` 下界）。

### 前置条件与安装

与 v1.4.0 相同：profile 需挂 `session-controller` 与 `workspace` 宿主行；换版本先 `remove` 再
`add`，装完**重启 Host**。

```bash
dsh plugin --profile <profile> remove dsh-agent-session-tools
dsh plugin --profile <profile> add https://github.com/chocobo77/dsh-agent-session-tools/releases/latest/download/dsh-agent-session-tools.tgz
```

### English

Behavior-fix release, no new tools or parameters; tests 78 → 82. `session_create` now **fails fast on
an unregistered `workspaceId`** (`session_create: workspace "…" not found (workspace/not-found)`)
instead of silently creating a default-cwd, ungrouped Session — the host registry's `get` answers
`undefined` rather than throwing, so the plugin converts that into the documented failure before any
session exists or any model selection is recorded. `session_error_audit` no longer blocks the host
event loop: directory walks and file reads use async fs, and zstd decoding runs on libuv's threadpool;
a missing sessions root now returns a tool-prefixed error instead of a raw filesystem exception. Pack
validation covers all four dist modules; Plugin Manager descriptions mention the third tool.
